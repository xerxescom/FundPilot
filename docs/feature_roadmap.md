# FundPilot 功能路线图

这份路线图按“真实可用性、当前代码基础、后续依赖关系”排序。核心方向是先把基金数据、指标和任务链路做稳，再扩展评分体系和异步能力，最后上新闻、Embedding 和混合模型。

## P0：基金数据抓取与指标分析

目标：让基金详情、评分、预警和 AI 简报都建立在稳定、可追踪的数据基础上。

优先事项：

- 多数据源兜底和失败重试。
- 净值、涨跌幅、指标完整性校验。
- 一键同步分析流程稳定化。
- 指标扩展：阶段收益、回撤、波动、夏普、胜率、相关性、持仓贡献。

验收标准：

- 数据同步失败时能显示明确原因。
- 自选基金能看到同步、指标、评分和报告状态。
- 指标缺失不会导致页面崩溃，而是引导用户补齐数据。

## P1：Redis Worker 异步分析任务

目标：把长任务从同步 HTTP 请求中拆出来，避免前端等待过久。

当前状态：

- 已提供第一版后台任务接口：`POST /api/v1/tasks/enqueue/{task_name}`。
- 任务中心支持“前台运行”和“后台运行”，后台任务状态写入 `TaskRunLog`。
- 当前后台执行器使用 FastAPI BackgroundTasks，后续可替换为 Redis Worker，前端契约保持稳定。

优先事项：

- 将同步净值、计算指标、计算评分、生成报告、新闻摘要等长任务放入异步队列。
- 任务中心展示排队中、执行中、成功、失败、耗时和错误原因。
- 保留当前手动任务入口，后端执行方式逐步切换为队列。

验收标准：

- 前端触发长任务后立即得到任务 ID。
- 任务中心可刷新查看状态和结果。
- 任务失败不会影响服务进程稳定性。

## P1：多策略基金评分体系

目标：从单一规则评分升级为适配不同使用场景的评分体系。

优先事项：

- 保留当前默认规则评分。
- 新增策略：稳健型、进攻型、低回撤型、持仓适配型、主题机会型。
- 每个策略输出分项分、总分、原因和适用场景。
- 前端评分排行支持切换策略。

验收标准：

- 用户能按策略筛选基金。
- 每个评分结果都能解释为什么得分高或低。
- 策略评分不输出直接买卖建议。

## P2：热点新闻摘要与主题关联

目标：解释“为什么关注”，把市场热点与基金主题连接起来。

优先事项：

- 抓取市场热点、行业新闻、基金主题相关信息。
- 将新闻归类到行业/主题。
- 在基金详情、今日驾驶舱、AI 简报中展示相关热点。
- 展示新闻来源、时间和可信度。

验收标准：

- 每条新闻都可追溯来源。
- 新闻只作为观察材料，不直接转化为买卖建议。
- 热点主题能关联到自选基金或持仓。

## P2：本地模型与在线模型混合推理

目标：在隐私、稳定性、效果和成本之间做可控切换。

优先事项：

- 本地 Ollama 作为默认模型。
- 在线模型作为可选增强能力。
- 根据任务类型选择模型：日报偏本地，新闻总结和复杂解释可在线。
- 增加模型状态、失败兜底、成本和隐私提示。

验收标准：

- 模型不可用时有规则兜底。
- 用户能看见当前使用的模型和失败原因。
- 在线模型不默认启用。

## P3：基于 Embedding 的基金语义检索

目标：让用户用自然语言找到相关基金、报告和风险线索。

优先事项：

- 对基金名称、主题、评分原因、AI 报告、新闻摘要建立语义索引。
- 支持自然语言搜索，例如“低回撤的科技基金”“最近评分下降的宽基”。
- 搜索结果展示命中原因和关联数据。

验收标准：

- 搜索结果能解释匹配原因。
- 语义检索结果不替代评分和风险校验。
- 可以回到基金详情、报告或新闻原文。

## P3：AI 投研观察与行动清单

目标：替代“AI 投资建议生成”，输出安全、可解释的观察清单。

允许输出：

- 建议观察什么。
- 风险在哪里。
- 为什么评分变化。
- 需要补充哪些数据。
- 适合放入哪类策略观察池。

禁止输出：

- 直接买入、卖出、重仓、清仓建议。
- 保证收益或确定性判断。

验收标准：

- 所有 AI 输出都遵守安全边界。
- 输出以观察、复盘、风险解释为主。
- 触发敏感表达时使用规则兜底。
